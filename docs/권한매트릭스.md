# [양식] 권한 Matrix
| Actor·Role | Resource·행동 | 인증 | Role | Resource 소유권·업무 조건 | 허용/거절 | 실패 |
| --- | --- | --- | --- | --- | --- | --- |
| (비로그인) | 게시글 목록·상세 조회 | 불필요 | - | 공개(`publiclyVisible=true`) 글만 | 허용 | - |
| 사용자 | 게시글 등록 | 필요 (X-User-Email) | User | - | 허용 | 401 |
| 의뢰자 | 자신의 게시글 수정·삭제·공개전환 | 필요 (X-User-Email) | User | `authorEmail` = 현재 사용자 | 허용 | 401 / 403(작성자 아님) |
| 사용자 | 타인의 게시글 수정·삭제 | 필요 (X-User-Email) | User | `authorEmail` ≠ 현재 사용자 | 거절 | 403 |
| 수리자 | 타인의 게시글에 제안 등록 | 필요 (X-User-Email) | User | 게시글 status = `WAITING` AND `publiclyVisible=true` | 허용 | 401 / 409(마감된 글) |
| 사용자 | 같은 게시글에 제안 중복 등록 | 필요 (X-User-Email) | User | - | **허용** (실제로 중복 제한 없음 — 기존 문서의 "409 이미 활성 제안 존재"는 실제 동작과 다름) | - |
| 의뢰자 | 자신의 게시글에 등록된 제안 목록 조회 | 불필요(공개 API) | - | - | 허용 — 실제로는 누구나 조회 가능(글 상세에 같이 노출) | - |
| 의뢰자 | 제안 채택(매칭 확정) | 필요 (X-User-Email) | User | `post.authorEmail` = 현재 사용자 AND 이미 채택된 제안 없음(post row 비관적 락) | 허용 | 401 / 403(작성자 아님) / 409(이미 채택된 제안 존재) |
| 수리자 | 자신이 보낸 제안 삭제 | 필요 (X-User-Email) | User | `repairerEmail` = 현재 사용자 AND 채택 전 AND 채팅방 없음 | 허용 | 403(본인 제안 아님) / 409(채택됨 또는 채팅방 존재) |
| 참여자(요청자·수리자) | 제안 단계 채팅방 생성·조회 | 필요 (Bearer) | User | 해당 제안의 당사자 | 허용 | 401 / 403 |
| 참여자 | 채팅방 목록·상세·상대방 조회 | 필요 (Bearer) | User | 해당 거래/제안의 요청자 또는 수리자 | 허용 | 401 / 403 |
| 참여자 | 채팅 메시지 전송·조회 | 필요 (Bearer, STOMP는 CONNECT·SEND·SUBSCRIBE마다 재검증) | User | 채팅방 참여자 | 허용 | 인증 실패 시 연결 거부 |
| 사용자 | 본인이 보낸 메시지 삭제 | 필요 (Bearer) | User | `senderId` = 현재 사용자 | 허용 | 403(타인 메시지) |
| 참여자 | 첨부파일 업로드·다운로드 | 필요 (Bearer) | User | 채팅방 참여자 | 허용 | 401 / 403 |
| 참여자 | 계약서 조회 | 필요 (Bearer) | User | 해당 거래의 요청자 또는 수리자 | 허용 | 401 / 403 |
| 참여자 | 계약 초안 작성(`draft`) | 필요 (Bearer) | User | 요청자 또는 수리자, 최신 계약이 `SIGNED` 아님 | 허용 | 409(이미 서명됨/버전 불일치) |
| 참여자 | 서명 요청(`request`)·서명(`sign`) | 필요 (Bearer) | User | 요청자 또는 수리자 | 허용 | 409(상태 불일치) |
| 수리자 | 작업 시작(`start`) | 필요 (Bearer) | User | 현재 사용자 = 수리자 AND **결제 완료** | 허용 | 403(수리자 아님) / 409(결제 미완료) |
| 수리자 | 완료 신청(`finish`) | 필요 (Bearer) | User | 현재 사용자 = 수리자 AND 거래 status = `REPAIRING`(또는 레거시 `PRODUCT_SENT`) | 허용 | 403 / 409(잘못된 상태) |
| **의뢰자** | **완료 확정(`accept`)** | 필요 (Bearer) | User | 현재 사용자 = **요청자**(수리자 아님 — 기존 문서와 반대) | 허용 | 403(요청자 아님) / 409(잘못된 상태) |
| 수리자 | 완료 확정(`accept`) 시도 | 필요 (Bearer) | User | 현재 사용자 = 수리자 | 거절 | 403 |
| 의뢰자 | 결제 생성 | 필요 (X-User-Email, `payerEmail`) | User | 계약이 `SIGNED` 상태, 금액이 채택 제안 금액과 일치 | 허용 | 409(중복 결제 `DUPLICATE_PAYMENT` / 이미 종료된 거래) |
| 수리자 | 자신이 받은 정산 내역 조회 | 필요 (X-User-Email) | User | `payeeEmail` = 현재 사용자 | 허용 | 401 |
| (모든 사용자) | 정산 확정(`settle`) | 해당 없음 — **브라우저에서 직접 호출 불가** | - | post-service 내부(계약 `accept` 처리 중)에서만 호출 | 거절(외부 호출 시) | - |
| 사용자 | 결제 웹훅(PortOne) | PortOne 서명 헤더 검증 | - | Caddy가 게이트웨이/BFF 없이 payment-service 직결 | 허용(서명 유효 시) | 서명 불일치 시 거절 |
| 참여자 | 완료된 거래에 후기 작성 | 필요 (X-User-Email) | User | 거래 status = `COMPLETED`, 해당 postId에 후기 없음(`postId` UNIQUE) | 허용 | 409(미완료 거래 / 이미 후기 있음) |
| 사용자 | 미완료 거래에 후기 작성 시도 | 필요 (X-User-Email) | User | 거래 status ≠ `COMPLETED` | 거절 | 409 |
| (비로그인 포함) | 특정 유저가 받은 후기·평점 조회 | 불필요 | - | 공개 정보 | 허용 | - |
| 사용자 | 후기 수정·삭제 | 해당 없음 | - | **후기 수정·삭제 기능 자체가 없음**(작성 후 불변) | 거절(기능 없음) | - |
| 사용자 | 내 이력서 작성·수정·삭제 | 필요 (X-User-Email) | User | `userEmail` = 현재 사용자 | 허용 | 401 |
| (비로그인 포함) | 타인 이력서 조회(`GET /api/resume/{email}`) | **불필요** | - | **서버는 제안의 `attachResume` 여부와 무관하게 이메일만 알면 누구나 조회 가능** — `attachResume`는 프론트 "이력서 보기" 버튼 노출 여부만 제어하는 클라이언트 단 편의 기능이며 서버 접근 제어가 아님 | 허용 | 404(이력서 없음) |
| 사용자 | 내 알림 조회·읽음 처리·설정 변경 | 필요 (X-User-Email) | User | `recipientEmail`/`userEmail` = 현재 사용자 | 허용 | 401 |
| 사용자 | 자신의 프로필·거래 내역 조회 | 필요 (X-User-Email) | User | 조회 대상 = 현재 사용자 | 허용 | 401 |
| (비로그인 포함) | 특정 유저(주로 수리자)의 거래 내역 조회(`/profile/{email}/transactions`) | **불필요** | - | 공개 정보로 간주, role 파라미터로 요청자/수리자 구분만 가능 | 허용 | - |
| 사용자 | 신고 접수 | 필요 (X-User-Email) | User | - | 허용 | 401 |
| 관리자 | 유저 목록 조회·권한 변경·정지 | 필요 (Bearer, 매 요청마다 DB에서 role 재확인) | Admin | - | 허용 | 401 / 403(Admin 아님) |
| 관리자 | 작성자 무관 게시글 삭제 | 필요 (Bearer) | Admin | - | 허용 | 401 / 403 |
| 관리자 | 신고 목록 조회·처리(해결/기각) | 필요 (Bearer) | Admin | - | 허용 | 401 / 403 |
| 사용자(비관리자) | 관리자 전용 기능 접근 시도 | 필요 | User | Role ≠ Admin | 거절 | 403 |
| 로그인 사용자 | AI 게시글 초안(`POST /api/ai/post-draft`) | 필요 (Bearer) | User | 로그인 사용자면 누구나 (게시글 소유권 무관 — 아직 작성 전 단계) | 허용 | 401 / 429(호출 한도) / 503(AI 비활성화) |
| 참여자 | AI 계약서 초안(`.../contract/ai-draft`) | 필요 (Bearer) | User | 해당 거래의 요청자 또는 수리자, 거래 status = `MATCHED` | 허용 | 403(당사자 아님) / 409(상태 불일치) |

## 판정 순서

1. 인증 유효성
2. Role
3. Resource 존재와 소유 관계
4. 업무 상태
5. Dependency 결과
6. 허용 또는 안전한 실패

민감 Resource는 추측 방지를 위해 404를 선택할 수 있으며 근거를 기록합니다. Dependency 장애를 권한 없음으로 오인시키지 않습니다.
